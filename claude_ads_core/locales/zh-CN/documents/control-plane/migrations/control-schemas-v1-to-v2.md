# 控制 schema 迁移：v1 到 v2

## 生态处置台账

版本 2.0.0 新增必需的公开及规范跟踪器快照，限制仓库标识符，移除未解决的决策和许可证状态，并要求每个条目至少有一个需求 ID。版本 1 文档仅对 `ecosystem-dispositions.v1.schema.json` 仍然有效。

2.0.1 检出已经生成快照字段，却仍将台账标记为 1.0.0，因此该实例不符合已发布的 v1 schema。版本 2 明确表达现有的破坏性结构，而不是重写 v1。

迁移时，应添加两个快照对象，将 `dependency-review` 替换为最终审查处置，将 `pending` 许可证审查替换为已完成的证据，并将 `schema_version` 设置为 `2.0.0`。

## 发布门禁评估

版本 2.0.0 新增漏洞例外完整性检查，并将已存储的生态检查重命名为 `ecosystem-ledger-integrity`。v2 报告恰好包含八项检查。版本 1 报告仅对 `release-gate-report.v1.schema.json` 仍然有效。

2.0.1 生成器已经输出八项检查，却将报告标记为 1.0.0，因此这些生成的报告不符合已发布的 v1 schema。使用方应在 v2 下重新生成候选证据，而不是重新标记旧报告。

生态台账检查证明冻结审查台账的内部一致性。当前 GitHub 完整性由远程 CI 负责，不得仅凭已存储台账推断。
